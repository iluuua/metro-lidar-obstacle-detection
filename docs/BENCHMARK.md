# Методика испытаний

Качество детектора оценивается на уровне объектов, кадров и работы системы целиком. Для сравнения версий нужен одинаковый вход, фиксированная конфигурация и независимые проверочные сцены.

## Набор проверок

| Сцена | Что проверяется |
| --- | --- |
| Свободный прямой и кривой путь | Ложные тревоги и устойчивость оси |
| Разные формы тоннеля | Повторное определение сечения и дальность анализа |
| Объект внутри габарита | Первое подтверждение и удержание обнаружения |
| Объект рядом с габаритом | Корректность проекции и учёт неопределённости |
| Редкие отражения | Работа с низкой плотностью облака |
| Пропуски и смена старта | Зависимость от истории |
| Повреждённый ввод | Проверки декодера и восстановление состояния |

Параметры подбираются на обучающей части. Проверочная часть остаётся фиксированной до завершения выбора. При небольшом числе записей указывайте это ограничение рядом с результатами.

## Метрики обнаружения

Для каждого объекта измеряются расстояние первого подтверждения, доля обнаруженных кадров после него и самый длинный перерыв. На уровне кадров считаются TP, FP и FN при заранее заданном правиле сопоставления рамок.

Разметка должна описывать наблюдение независимо от ответа детектора. Удержанные рамки, дубли кандидатов и кадры без достаточного обзора учитываются отдельно. У всех версий используются одни и те же правила.

Для свободного пути публикуются число ложных тревог, длина маршрута и число кадров. Агрегат без объёма проверки мало говорит о качестве.

## Геометрия

Сравнивайте ось после компенсации перемещения датчика. Отдельно оценивайте общий сдвиг и поворот, локальное изменение формы, изломы и скачки длины габарита.

Для дальней оси разделяйте область с опорными точками и экстраполяцию. Стабильная кривая может иметь систематическую ошибку, поэтому для проверки точности нужен независимый эталон или синтетическая геометрия.

## Нагрузка и история

Повторите прогон с другим начальным кадром, с регулярными и случайными пропусками. Сохраните фактический набор кадров, которые получила ROS-нода, и используйте его для сравнения с офлайн-ядром.

После сброса истории и при холодном старте результаты могут отличаться. Эти режимы должны быть явно указаны в отчёте.

## Производительность

Для расчёта кадра публикуйте p50, p95 и максимум. Укажите процессор, число потоков, версию сборки, количество точек, наличие прогрева и способ подачи данных.

Измерение `compute_ms` относится к вычислениям. `receive_to_publish_ms` включает путь через ноду. Для полного времени от сенсора потребуются синхронизированные часы и отдельный замер.

## Повторение синтетических проверок

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p test_tunnel.py
cmake -S core -B core/build -DCMAKE_BUILD_TYPE=Release
cmake --build core/build --parallel
ctest --test-dir core/build --output-on-failure
```

Синтетические тесты проверяют логику и геометрию. Итоги испытаний на конкурсных записях приведены как агрегаты в [PRESENTATION_STATS.md](PRESENTATION_STATS.md).
