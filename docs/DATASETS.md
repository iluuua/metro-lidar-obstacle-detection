# Входные данные и свои записи

Детектор принимает последовательность облаков `sensor_msgs/PointCloud2` в ROS 2. Для офлайн-проверки подойдёт ROS 2 bag с `metadata.yaml` и файлами `.db3`.

Оригинальные конкурсные записи и их разметка хранятся у команды отдельно. Для воспроизведения используйте собственные записи либо данные, на использование которых у вас есть разрешение.

## Структура папки

```text
datasets/
  my_recording/
    metadata.yaml
    my_recording_0.db3
```

Можно передать `run.sh` любую папку, содержащую такие записи. Скрипт монтирует её в контейнер как `/data` с доступом на чтение. Список доступных записей показывает команда `bags`.

## Поля облака

Декодер использует описание полей из `PointCloud2`, `point_step`, `row_step`, ширину, высоту и порядок байтов. Координаты `x`, `y`, `z` должны быть представлены поддерживаемыми числовыми полями. Поле `ring` необязательно.

Система анализа имеет оси `x` вперёд, `y` влево и `z` вверх. Перед запуском нужно проверить преобразование из системы датчика. Это особенно важно при установке датчика боком или при наличии нескольких облаков в одной записи.

Временная метка каждого облака используется для истории детектора. При повторном проигрывании с начала или переключении на другой источник выполните сброс истории либо перезапустите ноду.

## Проверка своей записи

Сначала проверьте список топиков

```bash
ros2 bag info /path/to/your/recording
```

Затем запустите детектор и проигрывание по [инструкции ROS 2](ROS2.md). В RViz проверьте направление осей, положение рельсов и габарита. Сравните исходное облако с `/metro/debug/cloud`.

Для измерений сохраните версию кода, конфигурацию, характеристики датчика и сведения о разметке. Отдельно отмечайте сцены свободного пути и сцены с препятствиями. [Протокол испытаний](BENCHMARK.md).

## Синтетические данные

Тесты создают прямые и кривые тоннели с заданной геометрией. У таких сцен известны ось пути и положение объектов, поэтому они подходят для проверки вычислений и регрессий без конкурсных данных.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p test_tunnel.py
```

Способы добавления своих препятствий и проверки геометрии описаны в [AUGMENTATION.md](AUGMENTATION.md).

## Производные файлы

Сгенерированные результаты держите в `output/`, а подготовленные данные браузерного просмотрщика в `viewer/data/`. Эти папки исключены из Git. При публикации своих результатов проверяйте права на исходную запись, разметку и полученные из них координаты.
