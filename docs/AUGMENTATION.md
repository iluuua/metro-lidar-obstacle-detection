# Синтетические препятствия

В синтетической сцене задаются ось пути, положение предмета и параметры сенсора. Добавление предметов в собственную запись помогает проверить тот же алгоритм на более сложном фоне.

## Геометрия

Предмет задаётся в координатах пути. После преобразования в систему сенсора строится видимая поверхность и выполняется выборка лучей. Плотность точек меняется с дальностью и угловым разрешением.

Отражения фона, закрытые предметом, удаляются по тем же лучам. Без этой операции вставка может оставлять стену позади предмета полностью видимой и создавать физически несогласованную сцену.

Геометрия пути для вставки задаётся независимо от проверяемого детектора. Иначе ошибка оси одновременно сместит предмет и изменит его эталон.

## Эталон

Сохраняйте истинную рамку и идентификатор вставленного предмета отдельно от ответа детектора. Правило пересечения с габаритом рассчитывается в той же системе координат, но по независимой геометрии.

Фиксируйте случайное зерно, исходную запись, параметры лучей, положение сенсора и конфигурацию вставки. При сравнении двух версий используйте один и тот же набор сцен.

## Набор опытов

Проверяйте предметы разных размеров на прямом и кривом пути, несколько дальностей и положений относительно оси. Добавьте контрольные сцены без предметов. Наблюдения снаружи области движения полезны для оценки ложных тревог.

У прореживания отражений есть конкретный смысл только при заданной модели сенсора. Такой опыт показывает чувствительность к плотности точек и не заменяет запись с реального расстояния.

## Программные средства

`eval/inject.py` содержит инструменты для геометрии вставок. По умолчанию используется аналитическая модель лучей. Калибровка конкретного лидара может передаваться пользователем отдельно.

Синтетический тоннель для тестов строится программно

```bash
python -m unittest discover -s tests -p test_tunnel.py
```

Для проверки проекции используются аналитические сцены с известной кривой. [Проверка координат](PROJECTION_AUDIT.md).
