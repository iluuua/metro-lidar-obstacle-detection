# Инженерные решения и проверка изменений

В проекте есть несколько способов проверить поведение детектора. Геометрические тесты проверяют вычисления на синтетических сценах. Офлайн-прогон проверяет полный кадр. ROS-проверка дополнительно охватывает транспорт, историю и возраст результата.

## Геометрия и история

Начальное приближение по предыдущему кадру помогает восстановить ось на редких отражениях. Оно также создаёт зависимость от начального кадра. Поэтому каждое изменение проверяется с несколькими стартами и после явного сброса истории.

Сглаживание изображения габарита и геометрия решения имеют разные задачи. Визуализация может сохранять длину при коротком провале измерений. Область анализа должна отражать геометрию текущего кадра.

Оценка кривизны по хвосту оси полезна для продолжения пути вдаль. Точность продолжения проверяется отдельно от его плавности. [Методика](BENCHMARK.md).

## Смена формы тоннеля

Качество совмещения с шаблоном используется для оценки опоры. Область платформы или ниши может менять часть сечения, а не всё сечение целиком. Диагностика должна показывать, какие срезы приняты и почему заканчивается измеренная область.

При оценке разных вариантов полезно сохранять оба результата на одном и том же входе. По ним видно, что изменилось в оси, проекции точек, кластеризации и подтверждении.

## Очередь кадров

При перегрузке накапливать длинную очередь невыгодно для актуальности ответа. В рабочем процессе есть один ожидающий кадр, который заменяется новым. Пропущенные кадры учитываются по временным меткам.

Замер только вычислительного ядра не отражает задержку DDS, копирования и планирования процесса. Для проверки очереди записываются возраст результата и число вытесненных кадров. [Интерфейс ROS](ROS2.md).

## Испорченные данные

Декодер проверяет описание полей и размер буфера. Для геометрии проверяются NaN, бесконечности, вырожденные облака и повторяющиеся точки. Сбой обработки должен сбрасывать частично обновлённую историю.

В `core/tools/fuzz.cpp` находится генератор повреждённых входов. Его можно собрать с проверками памяти

```bash
cmake -S core -B core/build-fuzz -DMETRO_FUZZ=ON
cmake --build core/build-fuzz --target metro_fuzz --parallel
```

## Сравнение реализаций

Эталон на Python и ядро C++ решают одну задачу. Сравнение на одинаковых облаках помогает обнаруживать регрессии при переносе вычислений. Для расхождений сохраняются конфигурация, версия библиотеки и минимальная воспроизводимая сцена.
